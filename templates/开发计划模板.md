# 开发计划模板（docs/开发计划.md）

> 这是给 AI 用的任务分解表。人不必读懂技术细节，只需确认：9 个阶段齐全、顺序正确、每阶段有测试节点与交付物。

---

## 阶段 0 — 脚手架
- 交付物：项目骨架 + 本地 Web 服务可启动
- 测试节点：启动脚本能跑起来，首页返回 200

## 阶段 1 — 数据层
- 交付物：本地数据库/文件存储层 + 迁移/建表 + 自动备份模块
- 测试节点：写入→读出→重启后读出→备份文件生成与恢复，全绿

## 阶段 2 — 公共框架
- 交付物：三区布局（左导航 + 中内容 + 上工具栏）、路由、主题变量层
- 测试节点：各模块入口可达，空状态正常渲染

## 阶段 3 — 首页总览
- 交付物：今日计划 + 模块待办汇总
- 测试节点：新增计划后总览同步出现（跨模块联动测试）

## 阶段 4 — 自媒体模块
- 交付物：五步流程流 + 已发布数据统计
- 测试节点：阶段推进正确、发布后可录数据

## 阶段 5 — 开发模块
- 交付物：项目 / 里程碑 / Bug 录入与筛选
- 测试节点：里程碑进度计算正确、Bug 可录入可筛选

## 阶段 6 — 咨询模块
- 交付物：客户档案 + 沟通记录时间线 + 删除
- 测试节点：沟通记录按时间追加、删除客户级联清理

## 阶段 7 — 健康 + 娱乐模块
- 交付物：健身/饮食日历化 + 娱乐条目
- 测试节点：按日期查询返回当天记录

## 阶段 8 — 集成与收尾
- 交付物：启动脚本（.bat/.command/.sh）、README、自动化测试全量跑通
- 测试节点：全量测试通过 + 双击脚本真实起服务验证

## 阶段 9 — 走查、修复、美化、开源
- 交付物：走查报告 + 原子化修复提交 + 三风格主题 + ZIP/README/GitHub
- 测试节点：每次修复后全量测试仍全绿；外观变更前后功能测试一致

---

## 阶段执行指令模板（每次发给 AI）

```
执行阶段【N】【名称】。
- 严格按 PRD 实现，不新增 PRD 之外的功能
- 完成后立即注入该阶段测试并运行，必须全绿
- 测试失败必须定位→修复→重测，禁止跳过或删减断言
- 交付：本阶段改了哪些文件、测试命令与输出、下一阶段
```
